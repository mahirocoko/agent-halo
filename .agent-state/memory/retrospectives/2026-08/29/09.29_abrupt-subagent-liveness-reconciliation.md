## AI Diary

I initially treated the disagreement as if one of the two products must be fake, but the evidence showed a more precise truth: both surfaces were honest about different owners. The Mods statusline watched the child process and cleared immediately; Agent Halo watched lifecycle events and deliberately tolerated long tools. The stale row was caused by my own test procedure—`TaskStop` killed the child before its mod could emit a terminal event. Owning that causality mattered because it stopped me from blaming the renderer or shortening every tool timeout. The best fix was already latent in Agent Halo: native runtime monitoring had exact PID and process-start identity, including missing and PID-reuse outcomes. My first integration attempt was not yet disciplined enough. The verifier showed that Runtime's process-grouped target was unsuitable for per-conversation liveness and that a persisted tombstone must not alter ordinary browser session semantics. A second verifier then challenged the 64-target boundary and history priority. Those corrections produced a cleaner split: grouped targets for resource presentation, per-conversation targets for active liveness, one bounded native request, and no synthetic completion history. I am satisfied with the final result because Mahiro observed the exact real failure mode resolve on the installed app. The session also reinforced that a human screenshot can reveal a cross-surface ownership mismatch that green unit checks cannot.

## Honest Feedback

Three friction points deserve direct acknowledgement. First, I created the stale `task_5` row myself by stopping the probe and initially presented the statusline test as complete without checking Agent Halo's independent lifecycle surface. Cross-surface QA should have been part of the first test plan. Second, my first Agent Halo patch reused process-grouped Runtime targets for liveness. That looked economical, but it silently collapsed multiple active conversations sharing one host and could leave one row stale. The verifier was right to refute it. Third, I overclaimed browser/demo isolation while the Runtime demo intentionally persists synthetic ended identities for its own panel tests. The corrected contract scopes isolation to session projection rather than erasing existing demo behavior. What went well was the evidence discipline after those misses: exact event tails, exact agent IDs, current native source, focused hostile examples, serial browser tests, two rounds of independent challenge, a real release build/install, and Mahiro-owned final observation. The resulting design avoids changing protocol history merely to repair presentation and keeps the native polling bounded.

## Lessons Learned

- Abrupt process termination is not a successful completion; project it as inactive unless a real terminal event says otherwise.
- Use exact PID plus process-start identity to reconcile local liveness and fail closed on PID reuse.
- Resource aggregation and per-conversation lifecycle reconciliation are different ownership jobs even when they share one native sampler.
- Safety caps need explicit priority rules so active truth cannot be displaced by historical presentation work.
- A live native acceptance probe must cover both the active state and the missing-terminal transition.
